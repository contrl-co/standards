# Changelog

Consumers pin a tag, so every entry here is something a consumer opts into
by rerunning `scripts/sync.sh`.

- PATCH: wording, typos, clarification that changes no behavior.
- MINOR: a new rule, or a rule that is relaxed.
- MAJOR: a rule that tightens and will fail existing code or review.

## Unreleased

### Fixed

- `check-prose.sh` no longer flags the US words analysis, organism, and
  initialism: the `-is` stems are spelled out in the pattern. It also runs
  on stock macOS bash 3.2, replacing `mapfile` with a while-read loop, so
  the gate works locally before it fails remotely.
- CI no longer cancels a running gate when a pull request title or body is
  edited. Only a new push supersedes the run that is checking it.
- The changelog's pointer to the ai-guidelines provenance now resolves:
  the file carries a provenance section naming the Confluence source and
  the by-hand re-sync rule.

### Changed

- Every template now carries the same seventeen non-negotiables. The Cursor
  and Copilot templates were missing scope discipline, faithful reporting,
  tracker narration, and branch names; CLAUDE.md and AGENTS.md were missing
  Conventional Commits, the comment rule, and naming. The CI template
  coverage check now requires a phrase from each rule, so the lists cannot
  drift apart again.
- The repository-specifics section of CLAUDE.md and AGENTS.md has a required
  shape: build-and-verify commands, a repo map, and domain invariants. An
  agent that cannot build, test, or map a repository guesses instead, and an
  empty free-form section was producing empty sections.
- `check-prose.sh` catches more attribution trailer shapes: `Generated by`
  as well as `Generated with`, the robot-emoji footer, and more tool names
  in `Co-Authored-By`.
- The pre-pull-request list in code-review.md puts a number on small: aim
  under 400 changed lines.
- `check-prose.sh` is vendored to consumers via `scripts/vendored.txt` and
  the README CI example, so the US-English and no-attribution gates reach
  every repository instead of only this one.
- code-review.md opens with the pull-request-only rule: protected branches
  take changes through pull requests, never direct pushes, even from an
  owner, even for one line.

### Added

- `standards/context.md`: what we build, where the code lives (GitHub org
  `contrl-co` authoritative, GitLab legacy read-only), and the invariants
  no change may weaken — no master key, canonical-output stability, fail
  closed, and no silently skipping tests. Referenced from the standards
  index and both instruction templates.

- `standards/ai-guidelines.md`, adapted from the company AI Guidelines page
  in Confluence (last modified 31 Jul 2026, retrieved 7 Aug 2026). Covers
  the cost asymmetry between generating and reviewing AI output, the
  pre-pull-request checklist, and ownership. Re-sync by hand when either
  copy changes; see the provenance section in that file.
- `standards/issue-tracker.md`. Tickets carry the ask, not a build log. No
  status narration once a pull request exists, one running comment rather
  than an append log, and comments only when a person has to act.
- `standards/agent-review-guide.md`, a prompt for an agent reviewing a pull
  request alongside a human. Lists what CI already gates so the agent skips
  it, the failure modes worth its attention, per-standard violation
  signatures, what it cannot verify, and an output contract that caps
  findings and forbids praise or diff summaries.
- Initial standards: agent boundaries, prose, commits, code review, and lint
  policy.
- Every pull request tracks a ticket, and branch names carry its key:
  `<type>/<TICKET-KEY>-<short-description>`, for example
  `fix/CONTRL-35-rotate-tap-token`. One written exception, for reverting a
  break on a protected branch. The type is a commit type and never a tool
  name, so `codex/` and `claude/` branches are rejected.
- Language notes for Go, Python, and Node with Vite. Python standardizes on
  uv: `pyproject.toml` plus `uv.lock`, both committed, `requirements.txt`
  generated and never an input, and every gate run through `uv run`. The
  Node document also carries the UI rules: dumb components, a single source
  for design tokens, and a demonstrable example of every visual state.
- Agent instruction templates for Claude Code, AGENTS.md, Copilot, and
  Cursor, each restating the same non-negotiables so a rule cannot exist for
  one tool only.
- `scripts/sync.sh` to vendor a pinned tag into a consumer repository.
- `scripts/vendored.txt`, the single list of which gate scripts reach
  consumers. `sync.sh` copies from it and `check-drift.sh` rebuilds the
  expected `.standards/bin` from the same list, so deleting a gate locally
  to stop it running fails the drift check.
- `scripts/check-drift.sh` to fail a consumer's CI when its vendored copy is
  edited, when a gate script is deleted, or when the tag it pinned is moved.
- `scripts/check-branch-name.sh` to gate the branch shape and the presence
  of a ticket key.
- `scripts/check-prose.sh` to gate the mechanically checkable prose rules
  rather than leaving them to review.
- `scripts/selftest.sh` to exercise sync and drift detection locally.
